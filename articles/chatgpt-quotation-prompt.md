見積書づくりで時間がかかるのは、単価の最終決定だけではありません。商談メモから項目を拾い、作業範囲と対象外を文章にし、顧客に確認すべき穴を洗い出す——ここにもかなりの時間が消えます。ChatGPTはこの「たたき台」の部分で使えます。一方、単価・値引き・税・合計・納期・支払条件は、人が社内基準と表計算（または見積システム）で確定します。

この記事では、そのまま使えるプロンプト、提出前の確認表、入力時の注意を実務向けに整理します。統計や成功事例は使いません。手順と役割分担の話です。

## AIに任せてよいこと・人が決めること

**任せてよいこと**

- 商談メモからの見積項目の洗い出し（項目名・数量案・単位・作業範囲の説明）
- 前提条件と対象外の文面案
- 顧客に確認すべき質問のリスト
- 社内向けのチェックリスト案

**人が確定すること**

- 単価、値引き、消費税、合計金額
- 納期、支払条件、有効期限
- 宛先・案件名・契約形態
- 社内の原価・粗利との突き合わせ

AIに「合計いくらが妥当か」と聞くのは避けた方がよいです。根拠のない数字が出やすく、そのまま提出すると危険です。プロンプト側で「金額は決めず［社内確認］と書く」と明示します。

## そのまま使えるプロンプト

次をコピーし、末尾に匿名化した商談メモを貼ってください。

```
あなたは見積書のたたき台を作るアシスタントです。
以下の商談メモから次を出してください。

1. 見積項目の案（項目名・数量・単位・作業範囲の説明）
2. 前提条件の文面案
3. 対象外（スコープ外）の文面案
4. 顧客に確認すべき質問（優先度つき）

制約:
- 単価・値引き・消費税・合計金額・納期・支払条件は決めず、必ず［社内確認］と書く
- メモにない情報は推測せず、推測した場合は行頭に「推測:」と明記する
- 顧客名・会社名はメモ内の仮名のまま使う（実名に戻さない）
- 出力はMarkdownの表と箇条書きにする

---
（ここに商談メモ。顧客名はA社、担当Bなどと匿名化する）
```

### 追記用プロンプト（項目が足りないとき）

```
さきほどの項目案に対し、抜けやすい次の観点を点検してください。
- 要件定義・キックオフ
- 修正回数の上限
- データ移行・初期設定
- サポート期間の有無
- 第三者ツールのライセンス費用の扱い

追加が必要なら項目を足し、不要なら「追加なし」と理由を書いてください。
金額はやはり［社内確認］のままにしてください。
```

## 入力前のセキュリティ注意

個人向けChatGPTでは、学習へのデータ利用が初期オンです。業務で使う前に「設定 > データコントロール > すべての人のためにモデルを改善する」をオフにするか、学習に使われないBusiness以上を使ってください。顧客名・原価は匿名化してから貼ります。

出典: [ChatGPT のデータ管理](https://help.openai.com/ja-jp/articles/7730893-data-controls-in-chatgpt)

## 提出前に確認するチェックリスト

AIの出力をそのままPDFにしないで、次を人が確認します。

- [ ] 宛先・案件名・日付が正しいか
- [ ] 作業範囲と対象外が、依頼内容・議事録と一致しているか
- [ ] 「推測:」と付いた行が残っていないか（残っていれば確認して確定か削除）
- [ ] 数量・単価・税・合計が社内基準・表計算と一致しているか
- [ ] 納期・支払条件・有効期限が入っているか
- [ ] 修正回数やサポートの扱いが口頭合意とずれていないか
- [ ] 禁止情報（原価・個人情報の実データ）が文面に混入していないか

この7項目を印刷またはNotionに置き、「提出前に必ず通す」と決めるだけでミスが減ります。

## 現場での進め方（短い流れ）

1. 商談後、メモを匿名化してプロンプトに貼る
2. 出てきた項目・前提・質問を、担当者が赤入れする
3. 単価とスケジュールは表計算／見積システムで確定する
4. チェックリストを通してから送付する

AIは「たたき台の速度」を上げる道具です。承認印を押す責任は従来どおり人にあります。

## うまくいかないときの調整

- 項目が粗すぎる → 追記用プロンプトで観点を足す。またはメモに「成果物の種類」「修正回数の合意有無」を追記して再実行する
- 金額を勝手に出す → 制約文が弱い。［社内確認］を再掲してやり直す
- 顧客向け文面が硬い／甘い → 「想定読者は先方の情シス担当」「営業向けの平易な日本語」などトーンを指定する
- 対象外が空欄のまま → 「やらないこと」を先に箇条書きしてから、前提条件とセットで再生成する

## 社内テンプレとして残すとよいもの

個人のチャット履歴にプロンプトが散らばると、属人化します。次を1枚の社内メモにまとめておくと再利用しやすいです。

1. 上記の基本プロンプト（制約文つき）
2. 追記用プロンプト（抜け観点の点検）
3. 提出前チェックリスト（7項目）
4. 匿名化の例（「株式会社○○の田中」→「A社の担当B」）
5. 学習設定の確認担当（個人向けを使う場合）

営業・情シス・経理で見積の責任範囲が違う会社では、「AIが書いたたたき台を誰が承認するか」も一文で書いておくとトラブルが減ります。金額の最終責任は見積権限を持つ人、文面の範囲説明は案件担当、という分担が分かりやすいです。

大同生命サーベイ（2026年1月）では、生成AIを「活用したことがない（現在は活用していないを含む）」企業が60%以上で、活用業務は「文書・資料作成」が71%と最多でした。見積のたたき台は、まさに文書作成の延長に置きやすい用途です。ただし活用が進んでも、金額確定まで自動化しない、という線引きがこの記事の主張です。

出典: https://www.daido-life.co.jp/knowledge/survey/202601.html

## まとめ

- AIは項目整理・範囲文面・確認質問まで。金額と条件は人が確定する
- プロンプトで「金額は出さない」「推測は明記」を必ず書く
- 提出前チェックリストを人が通す
- 入力前に学習設定と匿名化を確認する
